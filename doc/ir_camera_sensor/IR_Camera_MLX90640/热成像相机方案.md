自己 DIY 一个**热成像相机（Thermal Camera）**，核心其实不像普通摄像头那样用 CMOS，而是用**红外热辐射传感器**。

整体结构：

```
        被测物体
           ↓
   红外热辐射(8~14μm)
           ↓
      红外镜头(Ge锗镜片)
           ↓
   热成像传感器(FPA)
           ↓
   ADC/数字接口
           ↓
   MCU/FPGA/ARM
           ↓
   图像处理
           ↓
     LCD显示/存储
```

---

# 1. 热成像核心传感器（最重要）

热成像传感器叫：

> **红外焦平面阵列 FPA（Focal Plane Array）**

根据材料分：

---

## ① 非制冷微测辐射热计（Microbolometer）⭐ DIY最常用

这是现在手持热像仪主流方案。

原理：

每个像素里面有一个微小电阻：

```
红外辐射
    ↓
吸收层升温
    ↓
电阻变化
    ↓
检测温度
```

结构：

```
像素阵列：

+---+---+---+
| R | R | R |
+---+---+---+
| R | R | R |
+---+---+---+

每个R = 一个温度点
```

优点：

* 不需要制冷
* 功耗低
* 成本低
* 体积小

常见分辨率：

| 分辨率     | 用途    |
| ------- | ----- |
| 32×32   | 玩具级   |
| 80×60   | 入门热像  |
| 160×120 | 常见DIY |
| 256×192 | 不错    |
| 384×288 | 工业    |
| 640×512 | 高端    |

---

# 6. DIY难点在哪里？

不是读取传感器。

真正难的是：

## ① NUC校准

每个像素响应不同：

```
像素1:
100℃ -> 输出1000

像素2:
100℃ -> 输出1060
```

需要校正：

```
真实温度 =
gain × ADC + offset
```

---

## ② 发射率修正

不同材料：

```
黑色物体:
ε≈0.95

金属:
ε≈0.2
```

同样100℃：

红外辐射不同。

---

## ③ 温度算法

传感器输出不是：

```
温度℃
```

而是：

```
红外能量
```

需要：

Planck公式反推。

MLX90640 可以理解成：

> **一个只有 768 个像素的低成本红外热成像摄像头芯片。**

它不是传统意义的摄像头，而是：

```
看到红外辐射
      ↓
转换成温度数据
      ↓
输出 32×24 温度矩阵
```

然后 MCU 把这些温度点画成“热图”。

Melexis MLX90640 是 Melexis 公司推出的 32×24 红外阵列传感器。它内部有 768 个 FIR（Far Infrared）像素，并且带有工厂校准数据，通过 I2C 输出数据。([Melexis][1])

---

# 1. MLX90640 外观和内部结构

它本体其实很小：

```
        红外窗口
          ↓

       _______
      /       \
     |  FIR    |
     | ARRAY   |
      \_______/

       | | | |
       V V V V

      VDD
      GND
      SDA
      SCL
```

封装：

```
TO-39 金属封装
```

类似老式晶体管。

里面不是一个传感器：

而是：

```
32 × 24

= 768个红外探测单元
```

也就是：

```
第1行

■ ■ ■ ■ ■ ■ ■ ■

第2行

■ ■ ■ ■ ■ ■ ■ ■

...

第24行
```

每个点对应一个温度。

([Melexis][2])

---

# 2. 它到底检测什么？

注意：

它不是检测“温度”。

它检测：

> 物体发射出来的红外能量

物体：

```
人体
 |
 | 8~14μm红外
 |
 ↓

MLX90640
```

内部：

```
红外能量
     |
     ↓
热敏电阻变化
     |
     ↓
ADC采样
     |
     ↓
数字量
```

然后通过算法：

```
红外辐射
+
环境温度
+
芯片温度
+
校准参数

↓

实际温度℃
```

---

# 3. 输出的数据是什么样？

假设你读取一次：

得到：

```
float frame[768];
```

实际上：

```
frame[0]

  ↓

第0个像素温度


frame[767]

  ↓

第767个像素温度
```

例如：

```
32×24温度矩阵


25 25 26 26 27...
25 26 30 35 40...
25 27 35 60 90...
```

显示出来：

```
蓝 蓝 绿 黄 红

```

就是热成像。

# 7. ESP32能不能带？

可以。

但是有一个坑：

读取 MLX90640 不是简单读数据。

因为：

传感器输出的是：

```
RAW ADC值
```

需要计算：

```
EEPROM校准参数

+
环境补偿

+
非线性修正

+
发射率补偿

=

温度
```

算法量比较大。

所以：

ESP32：

✅ 可以

Arduino UNO：

❌ 不推荐

因为 RAM 和算力不足。

([SparkFun电子产品][6])

# 8. 一个完整DIY结构

比如 ESP32-S3 热像仪：

```
          MLX90640

              |
              |
             I2C

              |
              |

          ESP32-S3

        /          \

      LCD          SD卡

      |
      
    热图显示

```

软件流程：

```
while(1)
{

  读取768个RAW数据;


  mlx90640_GetFrame();


  mlx90640_CalculateTo();


  得到768个温度;


  最大最小归一化;


  映射颜色;


  LCD显示;


}

```
