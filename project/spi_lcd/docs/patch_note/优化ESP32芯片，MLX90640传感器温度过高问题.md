## 发热根因排查

**ESP32-S3 芯片 50℃+ 的三个根因（按影响排序）：**

1. **整个固件是 Debug 优化（-Og）编译的** —— 你的热像流水线全是浮点运算：3×3 中值滤波（768 点 × 9 元素排序）、双边保边滤波、每帧 `qsort` 768 个 float 算分位数、280×240 双线性放大（6.7 万像素）。-Og 下这些代码慢 2~4 倍，**两个核长期满载** → 240MHz 满负荷跑 = 最大功耗。这是最主要的发热源。
2. **CPU 锁死在 240MHz 且没有电源管理**（`CONFIG_PM_ENABLE` 未开）—— 等传感器下一帧的 ~60ms 空闲期 CPU 也在 240MHz 空转。
3. **每个子页都全屏送显（16fps）** —— LVGL 软件旋转渲染 + 全屏 SPI 传输 16 次/秒。

**MLX90640 发热原因：**

1. 设置页/相册/息屏时热像图被完全遮挡，但传感器仍以 16Hz 满速采集（33mA），流水线照跑；
2. ESP32-S3 和 LCD 背光的 PCB 热量传导给传感器 —— 芯片降温后传感器也会跟着降。

## 已实施的优化

### 构建配置（`sdkconfig` + sdkconfig.defaults）
| 配置 | 原来 | 现在 |
|---|---|---|
| 编译优化 | DEBUG (-Og) | **PERF (-O2)** ← 最关键 |
| CPU 频率 | 240MHz | **160MHz**（-O2 后 160MHz 跑 8fps 绰绰有余） |
| 电源管理 | 关闭 | **自动 light sleep** + tickless idle |

### 代码优化
- **`app_main.c`**：空闲自动进入 light sleep；关键引脚（电源自锁 IO36、屏幕复位、背光等）在休眠时保持状态，防止掉电/屏闪；LVGL tick 2ms→5ms；删掉每次触摸都打印的调试日志。
- **`ir_mlx90640_app.c`**：
  - 送显从 16fps 降到 **8fps**（只在整帧完成时刷新，LVGL 渲染+SPI 负载减半，画质无感）；
  - 设置页/相册/照片查看/息屏时：传感器降频到 **1Hz**（电流 33mA→约 20mA），流水线全停；曲线页降频到 4Hz 继续采样；
  - 每帧 qsort 768 个 float → **O(n) 直方图分位数**（4KB 静态表，省去对数级排序）。
- **`MLX90640_API.c`**：帧等待轮询 5ms→20ms，每帧 I2C 状态查询从 ~12 次降到 ~3 次，休眠窗口更长。

## 硬件建议（传感器侧）
- MLX90640 尽量远离 ESP32 模组和 LCD 背光 LED；
- 传感器周围 PCB 开槽/挖空隔离热传导，下方不做大面积铺铜；
- 这也是为什么"同样的硬件别人不热"——热像传感器对 PCB 热传导非常敏感，芯片降温后它也会明显降温。
